Lead Finder — Chrome Extension

What this does

The Lead Finder Chrome extension lets you push real LinkedIn profile data into the Lead Finder database. You browse LinkedIn profiles manually (with your premium membership), click the extension icon on a profile page, and the extension extracts the data, shows you a confirmation popup, and writes the result.

Important: The popup always shows. You have to click "Send" for every push. There is no silent-update mode.

Install (Chrome)

  1. Open chrome://extensions/ in a new tab.
  2. Toggle Developer mode on (top right).
  3. Click Load unpacked.
  4. Select this directory: /home/anthonyturgman/lead-finder/static/chrome-extension/
  5. The extension appears in the toolbar (a small blue square icon).

Install on the Chrome profile that is logged into your premium LinkedIn account. The extension inherits whatever access that profile has — and that profile alone.

Use

  1. Browse to a LinkedIn profile: https://www.linkedin.com/in/<slug>
  2. Click the Lead Finder icon in the toolbar.
  3. The popup reads the Experience section and pre-fills the form.
  4. Edit any field. The matcher shows you what it found:
    • Update existing contact — only shown if a matching contact was found in the database.
    • Create new contact at existing company — only shown if a matching company was found.
    • Create new company + new contact — always available.
    • Discard — always available. Records the discard in the audit log but writes nothing.
  5. Pick an action and click Send to Lead Finder.

Sync from server (Windows laptop workflow)

The extension's default API base is http://lsb-wsl.tail4f816e.ts.net:8798 (your Tailscale hostname), so it works from any device on your Tailnet without manual configuration.

If you keep the canonical extension files on a server (e.g. an RDP host running the lead-finder Python server), you can pull the latest files to your laptop as a zip:

# PowerShell on the laptop
$server = "http://lsb-wsl.tail4f816e.ts.net:8798"
$dst    = "C:\Users\AnthonyTurgman\OneDrive - Live Solutions\_AI Model Development\chrome-extension"
Invoke-WebRequest -Uri "$server/extension/download" -OutFile "$env:USERPROFILE\Downloads\chrome-extension.zip"
Expand-Archive "$env:USERPROFILE\Downloads\chrome-extension.zip" -DestinationPath $dst -Force
# Then: chrome://extensions/  → click "Reload" on Lead Finder.

The zip contains the same 10 files that live in static/chrome-extension/ on the server, with directory structure preserved. Extract over the top of your existing copy to update.

Update after code changes

During development, just refresh the extension on chrome://extensions/ after editing files. The "Service worker (invalid)" button appears if the manifest changed; click Reload on the extension card.

API settings

The popup has a Settings panel at the bottom (expand it). The defaults are:

  • API base URL: http://localhost:8798
  • API key: the value of lf_api_key in lf_config.json

If your Lead Finder is on a different host, change the API base URL. The API key never leaves the background service worker (Manifest v3 service workers are isolated from content scripts).

Known limitations

  • No headline extraction. Per the design, only the Experience section is read. Headlines are unreliable.
  • No silent updates. The popup always shows.
  • No automated scraping. You browse and click. The extension is a tool you drive, not a background scraper.
  • Premium LinkedIn required for some profiles. If LinkedIn returns a "limited profile" page, the Experience section may not load.
  • Date parsing is heuristic. LinkedIn's date format is human-readable ("Mar 2022 - Present") and may be parsed imperfectly in some edge cases.

Highlight-to-extract mode (Phase 3)

On any LinkedIn page, select text with your mouse. A small "Extract to Lead Finder" button appears near the cursor. Click it to capture the selection into the popup's Highlight Inbox. Useful for grabbing emails, phone numbers, or notes that aren't in the Experience section.

Audit log

Every push (including discards) is recorded in the pending_pushes table. The Audit page shows the last 50 pushes in a read-only view.
